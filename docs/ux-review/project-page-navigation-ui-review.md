## 2. Issues found
- 🔴 **Right rail, all 3 panels** → 25% of every viewport is bordered panels holding a heading + one button then ~300–850px of white (Offers, Sample QC) with no empty-state text/icon. The emptiest area owns the most space and nothing explains what an offer or QC report is → users can't act.
- 🟠 **Fixed 80/25 grid** → content ends x≈1265 while "Export Project Summary" and the three "Edit" buttons right-align to x≈1240, ~400–500px from the text they act on; full-height rail hairlines make emptiness read as a broken layout, not a panel.
- 🟠 **Nested scrollbars (Species / Specimen / Analytes)** → a ~10rem scroll area inside an already-scrolling page adds a second scrollbar and clips a row mid-text (an ontology ID cut in half) — looks like data loss.
- 🟠 **Collapsed "Objective"** → a ~760px pale bar whose content is just the word + chevron; the most important narrative metadata is one click away and 90% dead space.
- 🟠 **Weak floating `Edit`** → three identical pale pills (Project Design / Funding / Contacts) in grey-on-pale-blue that reads disabled, detached from their fields, and shaped identically to "Export Project Summary", "Add" and "Upload" → no primary vs secondary action exists anywhere.
- 🟠 **Duplicated identity** → "Q2IMMU - Immunotest" appears three times (navbar, H1, "Project ID and Title" value); the drawer compounds it by calling the same project just "Immunotest".
- 🟠 **Naming / IA** → the drawer says "SUMMARY" while the same concept is also `/info` and "Ontology Search" (Title Case, last in an ALL-CAPS list); experiments are drawer sub-items *and* rail items *and* peers of SUMMARY — nothing encodes project → experiment → view.
- 🟠 **Add-experiment affordance** → the wide layout offers only a bare "+" beside "EXPERIMENTS" (icon-only, ~20px, ambiguous) while the rail offers a labelled "Add" → two entry points, two labels, one meaning.
- 🟡 **Branding lives in the drawer** → removing it deletes the "Data Manager" wordmark and leaves the hamburger dead; the navbar carries no app identity, search or account name today. The amber "test instance" banner also uses warning colour for informational text, repeats on every page, and is the loudest element on a pale screen — it outranks the project title.
- 🔵 **Chips** → ontology IDs are tiny mono-looking text in pale-blue badges with the underline *inside* the chip (two stacked affordances) and all terms one colour, so origin isn't distinguishable; the three domain-chip accent colours encode nothing.
- 🔵 **Data-shape nits** → "Smoke Test Edit Immunopeptidomics" wraps in the rail but ellipsizes in the drawer (240px of fixed nav wasted); the Analytes box wraps alone leaving half a row blank; all three boxes are fixed-height whether they hold 2 or 3 items.

## 3. Design-quality critique (frontend-design lens)
Principles applied: one point of focus per band; deliberate type scale and <80ch line length; purposeful colour; "visual structure is information" (only number real sequences); generic-default tells; sentence-case active copy; empty state as an invitation to act.
- **Identity / focus:** no centre of gravity — seven band headings ("Project Design", "Experiment Information", "Funding Information", "Project Contacts", "Experiments", "Offers", "Sample QC") share one ~20px slate-grey weight, competing with each other and losing to the H1; the H1 is followed by the default stats row (date + avatars + chips), not a statement of what the project is.
- **Typography:** effectively one heading size and one body size — hierarchy rests on grey-vs-dark, not scale, so grey section titles read as secondary labels (wrong for a section title). No prose measure (the 760px Objective bar); data text (ontology IDs, emails, ORCID) looks like a different face from the chrome.
- **Colour / contrast:** near-zero chroma (white, off-white, pale lavender boxes, grey text, pale pills); only the amber banner and pink/amber chips are saturated, so the eye lands on a diagnostic notice. Pale pill labels at small size look close to the AA boundary — measure.
- **Generic-default tells present:** identical rounded cards, one small radius and one grey-lavender fill on everything; ALL-CAPS tracked eyebrow ("PROJECT"); ALL-CAPS list labels (SUMMARY / DATASETS / ACCESS / EXPERIMENTS); hyphen-joined "CODE - Title" meta; monospace micro-labels for IDs; the same pale pill for every action. Absent: gradient washes and "→" appended to link text — and the pastel domain chips are the one element with an actual point of view.
- **Copy:** mixed grammar — verbs (Export Project Summary, Upload, Add, Edit) against nouns (Objective, Species, Project ID and Title, SUMMARY, DATASETS, ACCESS, EXPERIMENTS); "Edit" is reused for three unscoped things; "Experiment Information" labels a code union, not a user's question.
- **Empty state:** three blank panels, zero guidance, no next step. (Fixture text like "Wow@Cool.Dude" is ignored as test data — the missing direction is the finding.)
**Recommendations** (drawer removed, two-row top nav, centred dynamic content):
1. *One loud band.* One centred column (`margin-inline:auto`, ~1400px, fluid `clamp()` gutter). Row 1: wordmark + project dropdown + account + search. Row 2: project destinations as horizontal items (Overview · Experiments · Datasets · Access · Settings) marked by weight + a bottom rule, not a filled pill. Render code/title once; meta as one small line; objective clamped to ~3 lines with "Show more" — never a grey collapsed bar.
2. *Rails only when they have content.* Offers (finances) and Sample QC (per-experiment) leave the summary; the page becomes one centred column. Empty projects get an actionable checklist in sentence case — "Add your first experiment", "Register samples", "Upload measurement metadata" — each a link that starts the action.
3. *One type scale, one data face.* ~14px/1.5 body; one 30–32px title; 16px near-black band headings (not grey); 13px grey meta; a single monospace used only for identifiers, so "this is an ID" is learned once.
4. *One name and one weight per action.* Exactly one solid primary ("Add experiment"); everything else text/outline; scope "Edit" ("Edit funding", "Edit contacts") and anchor it to its heading; drop the icon-only "+". If a progress band is added, make it a genuine sequence with counts ("2 experiments have no samples") — no decorative 01/02/03.

## 4. What to look into
- Hover/keyboard focus: ring on the pale Edit/Upload pills, hamburger, bare "+", Objective bar; tab order drawer → rail → content.
- Narrow (<1100px) and ultrawide behaviour of the 80/25 grid: horizontal overflow, rail collapse, the fixed 240px drawer.
- Experiment sub-navigation tab bar and experiment pages (not captured): four same-person icons, arrow "wizard" tabs, whether both layouts render identical navbar chrome.
- Measured WCAG AA contrast for grey band headings, pale button labels and the ~11–12px pastel chips; Species/Specimen scrollbars (overlay vs classic); dark mode / high contrast, where pale fills and blue chips appear to have no counterpart.

## 5. Overall impression
Legible and information-dense, but it reads as a metadata dump: identity stated three times, seven equally weighted grey headings, three empty rail panels owning a quarter of every viewport, and no signal about what to do next. It succeeds at "show which metadata the project has registered" and fails the landing page's real job — telling a researcher where the project stands and what step comes next. Highest-impact improvement: delete the three right-rail panels and the fixed 80/25 grid so the page is one centred column whose loudest first element is identity + an expanded-but-clamped objective, followed by a progress/next-step band, with an actionable checklist for empty projects.
